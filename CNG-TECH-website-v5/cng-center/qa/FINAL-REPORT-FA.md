# گزارش تحویل نسخه سوم — CNG TECH

## وضعیت بسته

- شامل کد منبع، خروجی پیش‌نمایش `dist/`، فرم درخواست پیگیری، API و پنل خصوصی PHP/MySQL و راهنماهای فارسی است.
- سایت هنوز روی دامنه نصب نشده است. خروجی همراه بسته **پیش‌نمایش noindex** است، نه نسخه منتشرشده.
- فرم بدون HTTPS، پایگاه‌داده و تنظیمات خصوصی فعال نمی‌شود. کد ورود یا پیامکی در فرم دریافت یا ذخیره نمی‌شود.

## اصلاحات نهایی

- پس از ثبت موفق، اطلاعات ورودی شخصی پاک و شماره پیگیری نمایش داده می‌شود. تازه‌سازی صفحه در همان نشست، شماره قبلی را بازیابی می‌کند و فرم بسته می‌ماند.
- فرم مالک بزرگسال و زیر ۱۸ سال، مشخصات والد و تماس جایگزین را به‌صورت شرطی مدیریت می‌کند.
- سیاست ارجاع PHP به `same-origin` تغییر کرد تا ورود پنل در مرورگر با `Origin: null` رد نشود. تنظیم هدرهای میزبان/CDN باید پس از نصب بررسی شود.
- اطلاعات درخواست به‌صورت رمزگذاری‌شده ذخیره می‌شوند؛ پنل مشاهده جزئیات، تغییر وضعیت و حذف دارد. پاک‌سازی زمان‌بندی‌شده نیازمند تنظیم cron است.

## نتایج آزمون

### تکرارشده هنگام بسته‌بندی

| بررسی | نتیجه |
| --- | --- |
| ساخت پیش‌نمایش | ۱۳ صفحه + 404 |
| بررسی ساختاری | ۱۴ صفحه HTML، ۳۰۵ ارجاع محلی و ۱۴ بلوک JSON-LD؛ موفق |
| آزمون‌های Node.js | ۸ آزمون موفق |
| آزمون واحد PHP | ۳۳ assertion موفق |
| بررسی نحو PHP | ۶ فایل منبع، تنظیمات نمونه و آزمون؛ بدون خطای نحو |

فرمان‌های قابل تکرار از ریشه پروژه با Node.js ۲۰+ و PHP ۸.۲+:

```sh
node scripts/build.mjs
node scripts/check.mjs
node --test
php tests/backend-unit.php
```

### آزمون‌های مرحله قبلی روی همین اصلاحات

این آزمون‌ها در مرحله بسته‌بندی دوباره اجرا نشده‌اند؛ گزارش ثبت‌شده همراه بسته است:

- `backend-report.json`: **۵۰ بررسی موفق** روی PHP 8.2/MariaDB محلی با داده ساختگی؛ شامل CSRF، کنترل مبدأ، رمزگذاری، جلوگیری از ثبت تکراری، نشست پنل، محدودسازی نرخ، حذف و انقضا.
- `requests-browser-report.json`: **۶۰ بررسی موفق** در Chromium محلی؛ شامل فرم در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰، ثبت بزرگسال/زیر ۱۸ سال، بازیابی شماره پیگیری، ورود پنل، وضعیت و حذف. خطای JavaScript گزارش نشده است.
- شماره‌های پیگیری در گزارش مرورگر مربوط به داده‌های مصنوعی آزمون هستند؛ گزارش از اطلاعات واقعی مشتریان استفاده نمی‌کند.
- `browser-report.json` و گزارش `REVISION-2-FA.md` سوابق مراحل قبلی‌اند، نه تأیید آزمون مجدد تمام صفحات در نسخه سوم. تصاویر پوشه `screenshots/` نیز از مراحل مختلف توسعه هستند.

## محدودیت‌ها و کارهای پیش از انتشار

- موفقیت staging محلی، تضمین عملکرد Apache/cPanel، گواهی SSL، cron یا امنیت هاست واقعی نیست. این بررسی‌ها جایگزین ممیزی امنیتی مستقل نیستند.
- نشانی دقیق، تصاویر واقعی مجاز، وضعیت دامنه/SSL و شرایط روز طرح باید تأیید شوند؛ ثبت درخواست به‌معنی ثبت‌نام رسمی یا تضمین پذیرش نیست.
- ابتدا `docs/DEPLOY-FA.md` و برای فرم `docs/REQUESTS-SETUP-FA.md` را اجرا کنید. تنظیمات خصوصی و کلیدها بیرون از web root نگهداری شوند.
- پس از تأیید محتوا، `node scripts/build.mjs --production` و سپس `node scripts/check.mjs` را اجرا کنید؛ فقط محتویات `dist/` روی هاست سازگار با PHP بارگذاری شود.
- روی هاست واقعی با اطلاعات ساختگی، ثبت و بازیابی درخواست، ورود/خروج پنل، حذف، انقضا، هدرها و cron را دوباره امتحان کنید. اطلاعات واقعی در پیش‌نمایش یا staging وارد نشود.
- ZIP فاقد پایگاه‌داده staging، تنظیمات خصوصی، کلیدها، گذرواژه عملیاتی و لاگ سرور است. نمونه تنظیمات در `deploy/config.example.php` عمداً همراه بسته قرار دارد.
