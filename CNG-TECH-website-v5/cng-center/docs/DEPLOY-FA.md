# راهنمای انتشار روی cngtech.ir

## ۱. تأیید اطلاعات

در `config/site.json` موارد زیر را بازبینی کنید:

- `site.url`: دامنه نهایی با HTTPS، بدون مسیر؛ در حال حاضر `https://cngtech.ir`.
- شماره تماس `09116438660`، ساعات شنبه تا پنجشنبه ۸ تا ۱۷ و موقعیت نشان.
- `business.address` و `postalCode`: فقط با اطلاعات واقعی تکمیل شوند. مختصات از روی لینک کوتاه حدس زده نشوند.
- شبکه‌های اجتماعی و واتساپ فقط پس از تأیید مالک افزوده شوند.
- اطلاعیه‌های قدیمی تضمین وضعیت روز نیستند؛ مبنای راهنمای طرح و منابع مقالات پیش از انتشار بازبینی شوند.
- تصاویر فعلی جایگزین‌اند. دستور تعویض در `IMAGES-FA.md` آمده است.

## ۲. ساخت خروجی عمومی

در پوشه پروژه:

```sh
node --test
node scripts/build.mjs --production
node scripts/check.mjs
```

در خروجی بررسی باید `mode=production` دیده شود. فایل `dist/build-info.json` نیز باید `"mode": "production"` داشته باشد. صفحات اصلی دارای `index, follow` و فایل `robots.txt` دارای `Allow: /` و آدرس sitemap خواهند بود. صفحه 404 عمداً noindex باقی می‌ماند.

**نکته:** اجرای دوباره `node scripts/build.mjs` بدون پرچم `--production` خروجی را به حالت پیش‌نمایش برمی‌گرداند و پوشه `dist` را از نو می‌سازد. همیشه پس از آخرین تغییر محتوا، build و check را دوباره اجرا کنید.

## ۳. هاست اشتراکی / cPanel / DirectAdmin

1. DNS دامنه را مطابق اطلاعات شرکت هاست تنظیم کنید.
2. برای دامنه اصلی و در صورت استفاده www، گواهی معتبر SSL فعال کنید.
3. از فایل‌های فعلی هاست نسخه پشتیبان بگیرید.
4. **محتویات داخل `dist/`** را در ریشه وب‌سایت، معمولاً `public_html/`، بارگذاری کنید؛ نه خود پوشه dist و نه کل پروژه.
5. فایل `index.html` باید مستقیماً داخل ریشه وب باشد و پوشه `assets` کنار آن قرار بگیرد.
6. برای Apache فایل نمونه `deploy/apache.htaccess` را با نام `.htaccess` در همان ریشه قرار دهید، پس از بررسی سازگاری با هاست.
7. مسیر ناشناخته باید با وضعیت HTTP 404 و محتوای `404.html` پاسخ داده شود؛ آن را به صفحه اصلی با وضعیت 200 هدایت نکنید.
8. در کنترل‌پنل هاست، انتقال HTTP به HTTPS و انتخاب دامنه canonical بدون www را فعال کنید. انتقال‌ها باید یک‌طرفه باشند؛ در صورت CDN/proxy با تنظیم SSL هماهنگ شوند.

Node.js و npm روی هاست لازم نیست؛ اما **فرم و پنل این نسخه به PHP، پایگاه‌داده MySQL/MariaDB و HTTPS نیاز دارند**. نصب را طبق `REQUESTS-SETUP-FA.md` کامل کنید و تنظیمات خصوصی را خارج از ریشه وب قرار دهید. `scripts/serve.mjs` فقط سرور پیش‌نمایش محلی است؛ برای میزبانی عمومی طراحی نشده است.

## ۴. Nginx یا میزبانی استاتیک

- برای نسخه دارای فرم، Nginx به PHP-FPM و تنظیمات امنیتی اختصاصی نیاز دارد؛ نمونه `deploy/nginx-location.conf` فقط استاتیک است و به‌تنهایی کافی نیست.
- **میزبانی صرفاً استاتیک:** پوشه‌های `api/` و `admin/` را پس از هر build از خروجی قابل انتشار حذف کنید تا فایل PHP به شکل متن عمومی نشود. فرم در این حالت کار نخواهد کرد. برای فرم فعال از هاست PHP استفاده کنید.
- روی سرویس استاتیک، publish directory را `dist` و build command را `node scripts/build.mjs --production` قرار دهید.
- صفحه 404 سفارشی و مسیرهای پوشه‌ای مثل `/services/` باید پشتیبانی شوند.
- این پروژه SPA نیست؛ قاعده بازنویسی همه مسیرها به `index.html` اضافه نکنید.
- سایت برای ریشه دامنه ساخته شده است؛ انتشار در مسیر زیرپوشه‌ای مانند `/cng/` نیازمند تغییر مسیرها در کد است.

## ۵. بررسی پس از نصب

- صفحه اصلی، خدمات، مقاله‌ها و مسیر `/calculator/` با HTTPS باز شوند.
- تماس موبایل و لینک نشان را روی تلفن واقعی امتحان کنید.
- صفحه محاسبه‌گر را با اعداد فارسی و قیمت‌های پرداختی خودتان آزمایش کنید.
- فونت، تصاویر و فایل‌های JS/CSS بدون خطای 404 بارگذاری شوند.
- `/robots.txt` و `/sitemap.xml` را بررسی کنید؛ هیچ `noindex` ناخواسته یا `X-Robots-Tag` از طرف هاست/CDN روی صفحات عمومی نباشد.
- مسیر ناموجود واقعاً وضعیت 404 داشته باشد.
- بعد از تغییر فایل‌ها، کش هاست/CDN را پاک کنید.

فرمان‌های اختیاری برای مدیر فنی:

```sh
curl -I https://cngtech.ir/
curl -I https://cngtech.ir/this-page-does-not-exist/
curl https://cngtech.ir/robots.txt
```

این دستورها صرفاً راهنما هستند؛ سایت در زمان تحویل روی دامنه منتشر نشده است.

## ۶. سئوی پس از راه‌اندازی

- مالکیت دامنه را در Google Search Console اثبات کنید؛ روش DNS مناسب است.
- اگر روش متاتگ انتخاب شد، فقط مقدار verification را در `site.searchConsoleVerification` وارد و سایت را دوباره build کنید.
- نقشه سایت `https://cngtech.ir/sitemap.xml` را ثبت کنید.
- چند URL را با ابزار URL Inspection و داده ساختاریافته را با ابزارهای گوگل بررسی کنید.
- نام، شماره و نشانی مرکز را در کانال‌های واقعی یکسان نگه دارید.
- انتشار منظم محتوای اصیل و عکس واقعی مفید است؛ هیچ تضمینی برای زمان ایندکس یا رتبه وجود ندارد.

## پیش‌نمایش خصوصی

نسخه عادی build شامل noindex و robots مسدود است، اما **این‌ها کنترل دسترسی نیستند**. برای پیش‌نمایش محرمانه روی اینترنت، رمز عبور یا احراز هویت هاست لازم است. پس از انتشار عمومی نیز robots را جایگزین سیاست حریم خصوصی نکنید.
