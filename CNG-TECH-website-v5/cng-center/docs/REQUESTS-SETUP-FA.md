# فعال‌سازی فرم درخواست و پنل خصوصی — cPanel

فرم، درخواست تماس و پیگیری را دریافت می‌کند؛ سامانه ثبت‌نام دولتی نیست و هویت، سن، اختیار قانونی و مالکیت سیم‌کارت/خودرو را استعلام نمی‌کند. داده واقعی را فقط پس از انجام تمام مراحل زیر بپذیرید. این کد جایگزین ممیزی مستقل امنیت یا بررسی حقوقی جمع‌آوری اطلاعات، به‌ویژه اطلاعات افراد زیر ۱۸ سال، نیست. ضرورت دریافت کد ملی/تولد در این مرحله و متن رضایت را مسئول کسب‌وکار تأیید کند؛ اگر ضروری نیستند فرم را فعال نکنید.

## ۱. پیش‌نیازها
- Apache 2.4/cPanel با PHP **۸.۲ یا جدیدتر و پشتیبانی‌شده**، افزونه‌های `pdo_mysql` و `sodium`، نشست PHP و MySQL 5.7+/MariaDB.
- دامنه و گواهی معتبر HTTPS. در cPanel دامنه مرجع را `https://cngtech.ir` قرار دهید و www/HTTP را به آن هدایت کنید. POST نباید از HTTP پذیرفته شود. بک‌اند عمداً X-Forwarded-Proto را از کاربر نمی‌پذیرد؛ در پروکسی از میزبان بخواهید HTTPS واقعی را صحیح به PHP معرفی کند.
- `display_errors=Off`، `log_errors=On` و لاگ خارج از web root؛ نشست‌های PHP در مسیر خصوصی همان حساب و با دسترسی محدود.
- دسترسی cPanel دارای احراز هویت دومرحله‌ای؛ برای `/admin/` ترجیحاً محدودیت IP/VPN یا لایه احراز هویت اضافه میزبان. خود پنل فعلاً MFA ندارد.

## ۲. بارگذاری
بعد از آزمون‌ها، `node scripts/build.mjs --production` و `node scripts/check.mjs` را اجرا کنید. **فقط محتویات `dist/`** از جمله `.htaccess` را در document root دامنه، معمولاً `/home/USER/public_html/`، بارگذاری کنید؛ پوشه پروژه، deploy، schema و تست‌ها عمومی نشوند.

خروجی build شامل `.htaccess` است؛ دستور PHP Handler ساخته‌شده توسط cPanel را پاک نکنید، تنظیمات را با آن ادغام کنید. `DirectoryIndex index.html index.php` و منع دسترسی به `lib.php`/فایل‌های مخفی لازم است. اگر 500 رخ داد تنظیمات AllowOverride را از میزبان پیگیری کنید؛ حفاظت‌ها را کورکورانه حذف نکنید.

فقط روی میزبان اجراکننده PHP بارگذاری کنید. روی Live Server/GitHub Pages/هاست استاتیک فایل PHP نباید به صورت متن دانلود شود؛ برای نسخه صرفاً استاتیک `api/` و `admin/` را از خروجی قابل انتشار حذف کنید (فرم غیرفعال می‌ماند). سرور `node scripts/serve.mjs` این مسیرها و PHP را مسدود می‌کند. نمونه Nginx قدیمی پروژه فقط برای صفحات استاتیک است؛ برای این نسخه به PHP-FPM و تنظیمات امنیتی اختصاصی نیاز دارد.

## ۳. پایگاه‌داده و پوشه خصوصی
۱. در MySQL Database Wizard یک پایگاه‌داده و کاربر اختصاصی بسازید. `deploy/schema.sql` را با phpMyAdmin وارد کنید. پس از ساخت جداول، کاربر برنامه فقط `SELECT, INSERT, UPDATE, DELETE` روی همان پایگاه‌داده لازم دارد؛ دسترسی ساخت/حذف جدول یا کاربران لازم نیست.
۲. **کنار document root، نه داخل آن**، پوشه `cng-private` بسازید. مثال:

```
/home/USER/public_html/api/requests.php
/home/USER/public_html/admin/index.php
/home/USER/cng-private/config.php
/home/USER/cng-private/cleanup.php
```

اگر document root متفاوت است پوشه خصوصی باید دقیقاً کنار آن باشد؛ مسیر کد `dirname(__DIR__, 2) . '/cng-private/config.php'` است. پوشه خصوصی را با alias/subdomain عمومی نکنید. مجوز پیشنهادی پوشه `700` و فایل‌ها `600` است؛ PHP باید به عنوان همان کاربر بتواند آن‌ها را بخواند.
۳. `deploy/config.example.php` را در مسیر خصوصی با نام `config.php` قرار دهید؛ اطلاعات DB، نام کاربری پنل و origin دقیق را تنظیم کنید. هیچ رمز آماده‌ای همراه پروژه نیست. `enabled` فعلاً false بماند.
۴. روی ترمینال خصوصی هاست کلید بسازید؛ خروجی را فقط در config خصوصی نگه دارید:

```sh
php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'
```

کلید برای رمزگذاری authenticated با Sodium secretbox استفاده می‌شود. تغییر/گم‌شدن آن باعث از دست رفتن دسترسی به درخواست‌های قبلی می‌شود. کلید را جدا از backup پایگاه‌داده و رمزگذاری‌شده نگه دارید؛ آن را به git، ایمیل، پیام‌رسان یا پوشه عمومی نفرستید.
۵. رمز پنل با مدیر رمز حداقل ۲۰ کاراکتری بسازید. برای جلوگیری از ثبت رمز در تاریخچه shell، در Bash خصوصی اجرا کنید:

```sh
read -rs -p 'Admin password: ' CNG_PASS; printf '\n'
printf '%s' "$CNG_PASS" | php -r 'echo password_hash(stream_get_contents(STDIN), PASSWORD_DEFAULT), PHP_EOL;'
unset CNG_PASS
```

هش خروجی را در `admin_password_hash` بگذارید؛ رمز خام در فایل نباشد. حساب مشترک ندهید. پنل یک حساب دارد و فاقد تاریخچه ممیزی فعالیت چندکاربره است.

## ۴. پاک‌سازی و پشتیبان
`deploy/cleanup.php` را کنار config خصوصی قرار دهید. Cron ساعتی cPanel با PHP CLI دارای pdo_mysql تنظیم کنید؛ مسیر PHP هاست ممکن است `/usr/local/bin/php` یا مسیر ea-php باشد:

```cron
0 * * * * /usr/local/bin/php /home/USER/cng-private/cleanup.php >> /home/USER/cng-private/cleanup.log 2>&1
```

یک بار دستی اجرا و نتیجه را بررسی کنید؛ خرابی cron باید به مسئول گزارش شود. در هر دسترسی به API/پنل نیز داده منقضی حذف می‌شود؛ cron برای حذف حتی بدون بازدید ضروری است. پاک‌سازی ساعتی ممکن است تا یک ساعت پس از مرز ۳۰روز طول بکشد. پس از پایان پیگیری، حذف زودتر از پنل انجام دهید. با تغییر `enabled=false` cron همچنان پاک‌سازی را اجرا می‌کند.

backupهای حاوی داده را رمزگذاری، دسترسی را محدود و چرخه حذف را **حداکثر ۳۰ روز** کنید. بعد از بازیابی، پیش از بازکردن سامانه پاک‌سازی داده‌های منقضی و درخواست‌های حذف‌شده را اعمال کنید. حذف ردیف معادل پاک‌کردن فوری از لاگ تراکنش/نسخه پشتیبان نیست؛ تنظیمات میزبان باید با سیاست اعلام‌شده سازگار باشند. اگر این تعهدات عملی نیست، فرم را فعال نکنید.

لاگ WAF/افزونه‌ها/APM نباید body فرم، کوکی، رمز، کد ملی یا شماره تلفن را ثبت کند. فقط IPهای مشتق‌شده با HMAC در جدول نرخ ذخیره می‌شوند؛ لاگ دسترسی هاست مستقل است و نگهداری کوتاه/محدود لازم دارد. اطلاعات به ایمیل یا پیام‌رسان ارسال نمی‌شود. هیچ سرویس بیرونی برای فرم فراخوانی نمی‌شود.

## ۵. فعال‌سازی و آزمون پذیرش
وقتی تنظیمات تکمیل شد `enabled=true` کنید. با داده ساختگی و بدون مدارک واقعی بررسی کنید:
- GET `/api/requests.php` پاسخ JSON شامل csrf و ticket می‌دهد؛ بدون پیکربندی 503 می‌دهد و فرم غیرفعال می‌ماند.
- حالت مالک بزرگسال، حالت زیر۱۸ سال/پدر یا مادر و تماس جایگزین درست باز/بسته شوند.
- بدون رضایت، کد ملی نامعتبر، تاریخ نامعتبر، شماره همراه نامعتبر یا CSRF نادرست ارسال رد شود. تاریخ شمسی فقط کنترل ساختاری دارد، نه اعتبار کامل تقویمی/سن.
- درخواست موفق شماره پیگیری محلی می‌دهد؛ تکرار همان فرم در همان نشست رکورد تکراری نمی‌سازد. پس از تازه‌سازی صفحه همان شماره نمایش داده می‌شود و فرم بسته می‌ماند. **برای درخواست مستقل دیگر، نشست/مرورگر جدا لازم است.** شماره پیگیری کد سامانه دولتی نیست.
- به `/admin/` بروید؛ ورود با رمز صحیح، خطای رمز غلط، خروج، مشاهده جزئیات، وضعیت و حذف را امتحان کنید. فهرست قبل از ورود نباید قابل‌مشاهده باشد. نشست پس از ۲۰ دقیقه بی‌فعالیتی یا ۸ ساعت از ورود منقضی می‌شود.
- کوکی `__Host-cng-session` باید Secure/HttpOnly/SameSite=Strict باشد. پاسخ پنل/API باید no-store/noindex داشته باشد. `robots.txt` سد امنیتی نیست؛ حفاظت از طریق نشست انجام می‌شود.
- سیاست ارجاع پنل را به `no-referrer` تغییر ندهید: مرورگر ممکن است هنگام POST فرم ورود `Origin: null` بفرستد و کنترل مبدأ آن را رد کند. کد PHP از `same-origin` استفاده می‌کند؛ ورود و خروج را پس از اعمال هدرهای Apache/CDN حتماً در مرورگر واقعی امتحان کنید.
- `/api/lib.php`، `/.htaccess`، `/config.php`، `/cng-private/config.php` قابل خواندن نباشند؛ هیچ پاسخ PHP شامل کد منبع نباشد. اگر PHP به شکل متن دیده شد فوراً آن مسیرها را از انتشار خارج کنید.
- در DB تنها payload رمزگذاری‌شده باشد؛ شناسه تصادفی، وضعیت و زمان به‌صورت واضح ذخیره می‌شوند. رمزگذاری DB در برابر نفوذ به کل حساب هاست کافی نیست چون کلید نیز روی همان هاست است.
- نتیجه موفق/خطا، نمایش موبایل و cron را روی هاست واقعی دوباره بررسی و داده ساختگی را حذف کنید.

## ۶. عملیات روزانه
ورود فقط از دستگاه مطمئن، عدم ذخیره/ارسال جزئیات بیرون از پنل، خروج امن پس از کار. هنگام تماس از مشتری **رمز یا کد پیامکی نخواهید**؛ خودش در سامانه رسمی وارد کند. اطلاعات پدر/مادر الزام رسمی تأییدشده یا تأیید ولایت/نمایندگی نیست. درخواست حذف/اصلاح پس از بررسی اختیار شخص از طریق تماس رسیدگی شود. در رخداد امنیتی ابتدا `enabled=false`، دسترسی را محدود و برای بررسی حرفه‌ای اقدام کنید؛ کلید را بدون برنامه مهاجرت عوض نکنید.
